## Синтаксис

```bash
libreyolo ui [key=value ...]
```

Аргументы — это пары `key=value`, POSIX-форма тоже работает, поэтому
`port=9000` и `--port 9000` — один и тот же аргумент.

## Аргументы

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `host` | `127.0.0.1` | Хост или интерфейс для привязки |
| `port` | `8000` | Порт для привязки. Если занят, берётся следующий свободный |
| `device` | `auto` | Устройство: `0`, `cpu`, `mps`, `auto` |
| `no_browser` | `false` | Не открывать браузер автоматически |
| `json` | `false` | Вывод JSON в stdout |
| `quiet` | `false` | Подавить stderr |
| `verbose` | `false` | Подробный вывод в stderr |

## Примечания

По умолчанию привязка идёт на loopback, поэтому интерфейс доступен только с
этой машины.

Если запрошенный порт занят, команда пробует следующий и так до двадцати портов
сверх запрошенного. Когда заняты все двадцать, команда завершается с `io_error`
и советует указать другой порт. В URL, напечатанном в stdout, стоит порт,
который действительно был занят, — читайте его, а не полагайтесь на тот, что
запросили.

Если не передан `no_browser=true`, вскоре после привязки по этому URL
открывается вкладка браузера.

Дальше команда работает на переднем плане до Ctrl+C, который корректно
останавливает сервер. Отсоединённого режима нет; если нужен свободный терминал,
уведите процесс в фон средствами оболочки.

`json=true` печатает URL и устройство одним объектом с `schema_version` до
старта сервера — так скрипт узнаёт занятый порт.

Смотрите также: [`libreyolo label`](/docs/cli/label) — рисование рамок и
сохранение разметки, [`libreyolo monitor`](/docs/cli/monitor) — наблюдение за
обучением. Оба — локальные веб-серверы с тем же поведением порта и браузера.
