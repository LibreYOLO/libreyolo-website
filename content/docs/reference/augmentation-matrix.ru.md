## Параметры

Это имена полей `TrainConfig`. `train()` и CLI также принимают короткие
написания из столбца CLI, поэтому `mosaic` задаёт `mosaic_prob`. В CLI `mixup`
направляется по задаче: для классификаторов это смешивание батчей при
классификации, для детекторов это `mixup_prob`. У `perspective` нет флага CLI,
и он задаётся из Python.

<aug-knobs />

Базовое значение по умолчанию — значение, заданное в самом `TrainConfig`.
Большинство семейств переопределяют некоторые из этих значений, а в разделе
[Значения по умолчанию по семействам](#defaults-by-family) приведены значения,
с которых запуск на самом деле начинается. Иллюстрации того, что делает каждый
параметр, есть на странице [Аугментации](/docs/train/augmentations).

Диапазоны в скобках — это интервалы, поэтому `[0, 1)` включает 0 и исключает 1.
Параметры классификации проверяются при сборке их пайплайна и вызывают
`ValueError` вне своего диапазона. Параметры детекции `TrainConfig` не
проверяет, поэтому со значением вне диапазона обучение молча продолжается.
Исключения составляют выпавший масштаб 0 или меньше и отрицательный
`perspective`: они вызывают `ValueError`, когда сэмпл искажается.

## Три статуса

| Статус | Значение |
|---|---|
| `used` | Параметр доходит до обучающего пайплайна семейства и меняет сэмплы |
| `gated_by_mosaic` | Параметр применяется только к сэмплам, прошедшим через ветку мозаики, поэтому при `mosaic_prob == 0` он никогда не срабатывает |
| `ignored` | Параметр никогда не доходит до пайплайна; если его задать, ничего не изменится |

Именно `ignored` стоит проверять до запуска, потому что ничего не падает. CLI
предупреждает, когда явно заданный параметр обучения игнорируется выбранным
семейством, а трейнер предупреждает, когда `mixup_prob > 0` не может сработать,
потому что семейство привязывает MixUp к мозаике, а `mosaic_prob` равен нулю.

## Какое семейство учитывает какой параметр

<aug-matrix />

Каждое охваченное семейство следует одному из шести пайплайнов. В пайплайне в
стиле YOLOX предобработка каждого сэмпла применяет HSV-джиттер и отражения, а
аффинное преобразование и MixUp выполняются только внутри ветки мозаики.
YOLO-NAS вместо этого выполняет для каждого сэмпла аффинное преобразование,
которое включено всегда, игнорирует мозаику и применяет MixUp независимо,
переиспользуя `mosaic_scale` как диапазон масштаба аффинного преобразования.

Пайплайн в стиле DETR — сквозное преобразование без мозаики. Фотометрическое
искажение, zoom-out и обрезка по IoU заданы в нём константами рецепта, а не
настраиваемыми параметрами, поэтому `hsv_prob` и геометрические параметры
никогда до него не доходят. Классификация использует `flip_prob` для
горизонтальных отражений и `flipud` для вертикальных. В семантической
сегментации джиттер масштаба и HSV берутся из атрибутов класса семейства, а не
из параметров конфигурации, а отражения в восстановлении выполняются как
связанные операции над входом и целью с фиксированной вероятностью 0.5.

`no_aug_epochs` учитывается везде, хотя отключает он разное: мозаику и MixUp в
стиле YOLOX, аффинное преобразование и MixUp в YOLO-NAS, сильные
фотометрические аугментации и обрезку плюс хвост расписания скорости обучения в
стиле DETR, а в классификации автоаугментацию, стирание, MixUp и CutMix.
Обрезка и отражения в классификации остаются включёнными.

Там, где семейство отличается от остальных семейств своего пайплайна, причина
одна из перечисленных ниже:

| Семейство | Отличие |
|---|---|
| `rtmdet`, `picodet`, `rtdetr`, `rtdetrv2` | `flipud` игнорируется: в их преобразованиях нет вертикального отражения |
| `fomo` | `perspective` и `flipud` игнорируются |
| `ppyoloe` | `flipud` игнорируется: исходный рецепт вместо него использует случайный поворот на 90 градусов |
| `yolo9`, `yolo9_e2e`, `yolo9_p2`, `yolo7`, `rtdetr`, `rtdetrv2` | `mixup_scale` игнорируется: их MixUp смешивает целые кадры в случайной пропорции и не масштабирует ни один из них |
| `gtr` | `mosaic_prob` и `mixup_prob` используются в первые `mosaic_epochs` эпох; `degrees`, `translate` и `mosaic_scale` задают аффинное преобразование, которое следует за мозаикой |
| `rfdetr` | `hsv_prob` игнорируется: в нативном пайплайне нет HSV-джиттера |
| `ec` | `hsv_prob`, `degrees` и `translate` используются только для `task="pose"`; detect и segment применяют фиксированные фотометрические рецепты |
| `dinov2` | Набор для классификации используется только для `task="classify"` |

`ec` и `dinov2` — многозадачные семейства, поэтому параметр помечается как
игнорируемый только тогда, когда его игнорирует каждая обучаемая задача
семейства. Так предупреждение CLI никогда не окажется неверным для одной задачи
и верным для другой.

Dome-DETR наследует преобразования D-FINE без изменений. Единственное, что ему
недоступно, — многомасштабное обучение, и отключает его конфигурация Dome-DETR,
а не спецификация аугментаций.

Охвачено тридцать одно семейство. Для семейства вне этого списка
`ignored_aug_params` возвращает пустое множество, поэтому предупреждение для
него не выводится.

## Значения по умолчанию по семействам

Значения, с которых начинается конфиг каждого семейства детекции. Пустая ячейка
означает, что семейство игнорирует этот параметр, поэтому его значение по
умолчанию ничего не меняет.

<aug-defaults />

Две закономерности важнее любого отдельного значения. RT-DETR, RT-DETRv2,
PicoDet и FOMO начинают с `mosaic_prob=0`, поэтому в этих семействах параметры,
помеченные в матрице как привязанные к мозаике, ничего не делают, пока мозаику
не включат. YOLOv9 начинает с выключенными поворотом, скосом и MixUp и с
`mosaic_scale=(0.5, 1.5)`, тогда как базовое значение по умолчанию равно
`(0.1, 2.0)`.

EdgeCrafter читает `hsv_prob`, `degrees` и `translate` только для
`task="pose"`, поэтому в его строке для этих трёх параметров указаны значения
по умолчанию для оценки позы.

Семейства классификации начинают с базовых значений по умолчанию:
`flip_prob=0.5`, `flipud=0.0`, `scale=(0.5, 1.0)`, собственный `crop_pct`
семейства, а `auto_augment`, `erasing`, `mixup` и `cutmix` выключены.

## Параметры, специфичные для семейства

Некоторые семейства держат параметры аугментации в собственном подклассе
`TrainConfig`, а не в базовом. CLI их не предоставляет; задавайте их через
Python API.

| Семейство | Параметр | Значение |
|---|---|---|
| `yolo9`, `yolo9_e2e`, `yolo9_p2` | `copy_paste` | Вероятность copy-paste-аугментации экземпляров, только `task="segment"` |
| `yolo9`, `yolo9_e2e`, `yolo9_p2` | `copy_paste_mode` | Источник copy-paste: `flip` отражает тот же сэмпл, `mixup` использует второй сэмпл |
| `yolo9`, `yolo9_e2e`, `yolo9_p2` | `rot90` | Вероятность случайного поворота на 90 градусов |
| `rfdetr` | `copy_paste` | Вероятность copy-paste для `task="segment"`, только в режиме `flip` |
| `rfdetr` | `copy_paste_mode` | Режим источника copy-paste для `task="segment"` |
| `rfdetr` | `crop_resize_prob` | Вероятность случайной обрезки с изменением размера в нативном пайплайне |
| `dfine` | `crop_resize_prob` | Вероятность случайной обрезки с изменением размера, `task="segment"` |
| `ec` | `crop_resize_prob` | Вероятность случайной обрезки с изменением размера, `task="segment"` |
| `ec`, `yolonas` | `brightness_contrast_prob` | Вероятность джиттера яркости и контраста, `task="pose"` |
| `ec`, `yolonas` | `affine_prob` | Вероятность аффинного преобразования с учётом ключевых точек, `task="pose"` |

`rot90` применяется к detect и OBB в `yolo9`.

## Запросы к спецификации

| Хелпер | Возвращает |
|---|---|
| `aug_support(family)` | Таблицу соответствия параметров и `Support` или `None` для неизвестного семейства |
| `ignored_aug_params(family)` | Множество имён параметров, которые семейство игнорирует; пустое для неизвестного семейства |
| `uses_mosaic_gating(family)` | Срабатывает ли MixUp у семейства только на мозаичных сэмплах |
| `display_name(family)` | Человекочитаемое имя семейства, которое используется в предупреждениях |
| `mixup_gating_warning(family, mosaic_prob, mixup_prob)` | Текст предупреждения, когда MixUp никогда не может сработать, иначе `None` |

`Support` — именованный кортеж из `status` и `note`, где примечание объясняет,
почему параметр для этого семейства игнорируется или привязан к мозаике. В
1.8.0 спецификация всё ещё помечает `mixup_scale` как привязанный к мозаике для
семейств, которые обучаются через обёртку мозаики YOLOv9, поэтому `aug_support`
сообщает о нём для этих семейств как о привязанном к мозаике, хотя матрица
выше, сверенная с пайплайном, помечает его как игнорируемый.

## Привязка к мозаике

Для семейства в стиле YOLOX сочетание `mixup_prob=0.5` и `mosaic_prob=0`
полностью отключает MixUp, потому что MixUp применяется только к мозаичным
сэмплам. К такой комбинации легко прийти, отключая мозаику на поздних этапах
обучения. Трейнер пишет в лог предупреждение с названием семейства, а
`mixup_gating_warning` — чистая функция, которая за ним стоит.
