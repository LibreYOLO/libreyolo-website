## 지원 계층 내보내기

호출 성공 여부를 결정하는 계층. 이것은 `(family, task, format)`의 세 쌍에 적용되며, 모든 조합에는 정확히 하나가 있음.

| 계층 | 의미 | `export()`에서 발생하는 일 |
|---|---|---|
| `validated` | 숫자 패리티는 CI에 포함되어 있거나 문서화된 야간 실행에서 확인됩니다 | 실행 |
| `available` | 변환은 구현되었지만 숫자 런타임 패리티 증거는 기록되지 않았습니다 | 실행 |
| `blocked` | 지원되는 경로가 없습니다 | 사전 점검(preflight)에서 `NotImplementedError`를 발생시키며, 그 이유를 제공합니다 |

검증되었고 사용 가능한 항목은 모두 확인 응답이나 일반 경고 없이 진행됩니다. 차이는 허가가 아닌 증거입니다: 검증된 항목은 패리티 테스트와 `since` 릴리스를 갖추고 있으며, 사용 가능한 항목은 아직 그렇지 않습니다. 예를 들어 macOS 예측 실행 없이 CoreML 변환은 사용 가능하지만 검증되지 않은 항목입니다.

차단된 조합은 종속성 확인, 보정 로딩, 추적 또는 아티팩트 생성 전에 실패하므로 일부만 쓰여지는 일은 없습니다.

모든 검증된 셀은 일반적으로 고정 입력 캔버스, 배치 1, FP32 및 명명된 런타임 버전에서 유래한 패리티 숫자의 구성을 설명하는 제약 조건을 가지고 있습니다. 이것을 일반적인 형식보다는 해당 구성에 대한 주장으로 읽으세요. 명시적인 항목이 없는 셀을 채우는 규칙은 [수출 매트릭스](/docs/reference/export-matrix) 페이지에 있습니다.

## API 계층

호출 모양을 결정하는 계층. 한 패밀리는 정확히 하나의 계층에 속하며, 아키텍처가 아니라 호출 계약에 의해 선택됩니다.

| 계층 | 팩토리 | 계약 |
|---|---|---|
| 디텍터 팩토리 | `LibreYOLO` | 하나의 프롬프트 없는 순전파는 캘리브레이션된 점수와 함께 발견된 모든 객체를 반환합니다. 멤버들은 체크포인트를 인식하여 등록합니다. |
| 프롬프트 가능한 세분화 | `LibreSAM` | 호출 시 제공되는 이미지별 공간 또는 개념 프롬프트 없이는 포워드는 의미가 없습니다. 인터랙티브하고 상태를 유지함: 한 번 인코딩하고 여러 번 프롬프트 제공 가능 |
| 오픈 보캐뷸러리 탐지 | `LibreOpenVocab` | 텍스트 조건화된 판별 탐지기. 클래스 목록은 프롬프트이며 `set_classes`가 설정합니다 |
| 비전-언어 | `LibreVLM` | 탐지기로 구동되는 생성 모델. 클래스 목록은 프롬프트이며 신뢰도는 자리 표시자입니다 |

세 가지 형제 계층은 의도적으로 탐지기 팩토리에 등록되지 않기 때문에 `LibreYOLO("some-alias")`가 이들에게 도달하지 않습니다. 이들은 체크포인트 스니핑 대신 크기 별칭으로 로드하고 자동으로 다운로드합니다.

네 가지 모두 동일한 `Results`를 반환하므로, 후속 코드는 이들 사이에서 변경되지 않습니다. 차이는 어떤 메서드가 작동하는지에 있습니다: 형제 계층은 `train()`, `val()`, `export()`에 대해 `NotImplementedError`를 발생시키고, SAM 및 오픈 보카뷸러리 계층은 `track()`에 대해서도 발생시킵니다. 각 계층 페이지에는 자체 제외 항목이 나열되어 있습니다.

## 커버리지 그룹

교차 패밀리 테스트 실행에 포함되는 패밀리를 결정하는 분류이며, 독자가 모델 페이지에서 가장 자주 만나게 되는 분류입니다. 등록된 모든 패밀리는 정확히 하나의 그룹에 등록되며, 등록된 패밀리가 등록에서 누락되면 테스트는 실패합니다. 아래 의미(MEANING) 열의 출처는 `GROUPS`이며, 동일한 파일의 `MODEL_GROUPS`는 모든 패밀리를 할당하고, Families 열은 해당 할당을 직접 계산합니다. Label 열은 사이트가 모델 페이지 헤더에서 동일한 그룹에 사용하는 짧은 이름입니다.

| 그룹 | 레이블 | 패밀리 | 의미 |
|---|---|---|---|
| `g0` | 플래그십 | 2 | 공유 기능 범위에서 필요한 플래그십 앵커 |
| `g1` | 코어 | 10 | 학습 가능한 탐지기 범위 세트 |
| `g2` | 지원됨 | 14 | 추가 학습 가능 패밀리 커버리지 세트 |
| `g3` | 추론 전용 | 35 | 학습 구현이 없는 패밀리 |
| `g4` | 박물관 | 5 | 추론 커버리지가 있는 역사적 패밀리 |
| `s` | 형제 계층 | 21 | 별도로 다루는 형제 API(SAM, 오픈 보캐브, VLM, 제로샷) 커버리지 |

이는 여섯 그룹에 걸쳐 87개의 패밀리입니다. `g3`만으로도 나머지 모든 그룹을 합친 것보다 더 많은 패밀리를 보유하고 있으며, 레지스트리의 대부분이 실제로 학습된 탐지기가 아닌 추론 전용 계통과 박물관 커버리지이기 때문입니다.

모델을 선택하는 독자를 위해, 그룹은 계열의 정확도가 얼마나 되는지가 아니라 엔지니어링 주의를 어디에서 기대해야 하는지를 알려줍니다. `g0`와 `g1`는 새로운 기능이 설계되어 처음으로 적용되는 곳입니다; `g2`는 CI에서 항상 녹색으로 유지되지만, 기능이 같은 릴리스 주기에서 나오기보다는 기회가 있을 때 적용됩니다. `g3`는 한계를 나타내기보다는 부재를 나타냅니다: 예측하고, 검증하며, 계열이 지원하는 경우 내보내기까지 모두 작동하고, `train()`는 `g3` 또는 `g4` 계열에서 무언가를 조용히 부분적으로 하지 않고 이유를 `NotImplementedError`로 명명합니다. `s` 계열은 전혀 이러한 균형에 있지 않으며, `LibreYOLO()`가 아닌 자체 팩토리을 통해 로드되기 때문입니다. 체크포인트 파일 이름을 읽을 때 그룹이 작업, 계열, 크기와 어떻게 함께 맞춰지는지에 대해서는 [핵심 개념](/docs/concepts)을 참조하십시오.

그룹은 사용자 중심 기능을 스스로 부여하거나 제한하지 않습니다. 지원은 해당 계열이 구현한 API와 형식별 기능 검사에서 제공되며, 그룹 구성원 여부 자체에서 나오지 않습니다. 그룹은 작업이 아닌 계열을 분류하므로, 작업 범위의 커버리지 실행은 "g1 detect"처럼 작업 이름을 명시적으로 지정합니다.

그룹을 실행 시간에 읽는 곳은 테스트에서만 읽는 것이 아니라 두 곳입니다. `collect_model_inventory()`에서 `libreyolo/models/inventory.py`는 CLI 인벤토리가 출력하는 모든 항목에 그룹을 연결하고, `pretrained=False`는 `g0` 및 `g1`의 계열에 대해서만 처음부터 다시 초기화되는 특별 경로를 트리거합니다. 그 두 그룹 외부에서는 `libreyolo/models/base/model.py`에서의 검사가 완전히 건너뛰어지므로, `pretrained=False`는 계열 자체의 `train()`에 일반 키워드로 도달합니다.

## 학습

`g3` 또는 `g4`의 계열에는 학습 구현이 없으며, `train()`를 호출하면 하나의 인스턴스가 발생합니다. 이는 계열 코드의 속성이지 그룹의 속성이 아닙니다: 그룹은 그 사실을 기록할 뿐 그것을 발생시키지는 않습니다.

학습을 수행하는 계열의 경우, 개별 증강 노브가 파이프라인에 도달하는지는 별개의 문제이며, `used`, `gated_by_mosaic`, `ignored`라는 자체의 3값 어휘를 갖습니다. [증강 매트릭스](/docs/reference/augmentation-matrix)를 참조하십시오.

## 계층이 말해주지 않는 것

계층은 정확도 주장(accuracy claim)이 아닙니다. 검증된 내보내기는 해당 아티팩트가 명시된 임계값 내에서 본래 모델을 재현한다고 말하며, 본래 모델이 데이터셋에서 얼마나 잘 점수를 내는지에 대해서는 언급하지 않습니다. 벤치마크 수치는 모델 페이지에 나와 있습니다.

A 티어도 라이선스 명시가 아닙니다. 가중치 라이선스는 같은 계열 내에서도 다양하며, 특정 체크포인트를 호스팅하는 저장소가 권위 있습니다. 탐지기 팩토리에 계열이 있다고 해서 그 공개된 가중치가 상업적 사용을 허용하는지에 대한 정보는 제공하지 않습니다.
