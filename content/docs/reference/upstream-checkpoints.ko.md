## 로드 시 일어나는 일

`LibreYOLO()`가 이미 완전한 v1.0 체크포인트가 아닌 `.pt` 파일을 만나면, 자동 변환기를 호출하며, 이 변환기는:

1. 공통 업스트림 레이아웃에서 텐서 딕셔너리를 풀어냄;
2. 는 등록된 각 패밀리에게 업스트림 이름이 네이티브 포트와 다를 경우 키를 재매핑하면서 레이아웃을 인식하는지 묻습니다;
3. 는 승자 모델을 엄격한 v1.0 메타데이터 체크포인트로 래핑하며, 텐서 자체에서 크기, 작업 및 클래스 수를 읽어 파인튜닝된 체크포인트가 올바르게 변환되도록 합니다;
4. 는 원본 옆에 `<source>-<Prefix><size>[-task].pt`로 작성하고 해당 경로를 반환하여 팩토리가 정상적으로 로드하게 합니다.

호출자에게 요구되는 사항은 없습니다. 어떤 패밀리도 주장하지 않는 파일은 아무 것도 반환하지 않으며, 팩토리는 불러올 수 없음을 보고합니다.

## 그것이 풀어내는 레이아웃들

텐서 딕셔너리는 EMA부터 시작하는 이 선호 순서에서 찾으며, 각 후보를 실제로 텐서를 포함할 때까지 시도합니다. 따라서 비어 있거나 메타데이터만 있는 EMA 블록은 아래의 유효한 가중치를 가리지 않습니다.

| 키 | 참고 |
|---|---|
| `ema.module` | 일반적인 EMA 래퍼 |
| `ema` | 텐서를 직접 저장하는 이전 플랫 EMA 래퍼 |
| `ema_state_dict` | `module.` 접두어 아래의 항목은 제거됩니다 |
| `params_ema` | |
| `params` | |
| `ema_net` | |
| `net` | |
| `model` | |
| `state_dict` | |
| 파일 자체 | 일반 상태 딕셔너리 |

각 후보는 텐서 값 항목으로 좁혀지고 정규화됩니다: 선행 `module.` 또는 `_orig_mod.` 접두어가 제거되며, 키가 모두 `model.model.`로 시작하는 딕셔너리는 해당 접두어가 제거됩니다.

## 어느 패밀리가 무엇을 인식하는지

Recognition은 per-family classmethod입니다. 기본 구현은 키가 이미 네이티브 포트와 일치하는 레이아웃을 주장합니다. 상류 키 이름이 다른 패밀리는 이를 remap으로 재정의하며, 인식하지 못하는 레이아웃에 대해서는 아무 것도 반환하지 않습니다.

Remapping 인식기를 제공하는 패밀리: `centernet`, `deeplabv3`, `deformable_detr`, `dexined`, `moge2`, `picodet`, `rtdetr`, `rtdetrv2`, `rtdetrv4`, `rtmdet`, `segformer`, `swin`, `teed`, `yolo7`, `yolo9`, `yolo9_e2e`, `yolo9_p2`.

자동 변환을 거부하는 패밀리: `efficientdet`, `eomt` 및 `pidnet`는 인식기에서 아무 것도 반환하지 않으므로, 상류 파일은 대신 변환 스크립트를 거칩니다. `l2cs`는 재배포 제한이 있는 추론 전용 가중치를 가지고 있으므로 일반 인식기에서 제외됩니다.

RF-DETR은 자체 인식기를 유지합니다. 이는 크기를 감지하고 COCO 클래스를 재매핑하기 위해 텐서 딕셔너리만이 아니라 전체 체크포인트가 필요하기 때문입니다. 이는 선택적 종속성이 설치될 때에만 등록됩니다.

다른 모든 등록된 패밀리는 기본값을 사용합니다: 자체 로더가 이미 해당 키를 인식할 때 파일을 주장합니다.

## 어떤 패밀리가 승리하는가

여러 패밀리가 동일한 파일을 주장할 수 있으므로, 해결 방식은 팩토리의 디스패치 규칙을 반영합니다.

하위 클래스의 주장은 상위 클래스보다 우선합니다. 등록 순서는 클래스 생성 순서를 따르므로, 파생 패밀리는 이를 다듬는 기반 클래스 이후에 등록되고, 그 긍정적 마커는 기반 클래스의 더 넓은 패스스루보다 패배하지 않아야 합니다.

구체성(encodes specificity)을 나타내므로 등록 순서가 최종 결정을 내립니다: 가장 먼저 주장된 것이 가장 구체적인 일치입니다.

깨질 수 없는 하나의 연결 레지스트리 순서는 아키텍처 키가 동일한 DEIM과 D-FINE에 대한 것입니다. 오직 그 경우에만 파일 이름이 결정적인 신호가 되며, 이름에서 힌트를 주지 않는 파일은 추측하지 않고 거부됩니다. 파일 이름은 다른 어디에도 의도적으로 참조되지 않으므로, 파일 이름만으로 더 일반적인 잘못된 긍정 주장이 더 구체적인 주장보다 우선될 수 없습니다.

## 안전한 로딩

업스트림 파일은 가중치 전용 언픽클러를 통해 로드됩니다. 일부 업스트림 학습 체크포인트는 언픽클러가 거부하는 라이브러리 객체를 포함하고 있습니다. 이러한 객체들은 가중치가 아니라 학습 메타데이터이므로, 차단된 각 전역 객체는 아무것도 실행하지 않고 언픽클러 요구를 만족시키는 비활성 대체 클래스로 재시도됩니다. 캡처된 이름은 문자열 레이블로만 사용되며, 절대 임포트되거나 평가되거나 호출되지 않습니다.

민감한 모듈 이름은 무조건 거부되며 절대 스텁되지 않습니다: `builtins`, `os`, `sys`, `posix`, `nt` 및 `subprocess`. 재시도 루프는 32회 시도로 제한되므로, 무한한 일련의 고유 글로벌을 도입하도록 설계된 파일은 스피닝하지 않고 실패 상태로 종료됩니다. 변환된 체크포인트에는 텐서만 남습니다.

## 변환된 파일의 위치

출력은 소스 옆에 작성되며, 이름은 `<source>-<Prefix><size>[-task].pt`입니다. 항상 새로 작성되며 재사용되지 않기 때문에 동일 소스를 반복 로드할 때 최신 상태가 유지되며, 동일한 디렉토리에서 공식 가중치나 동일 계열, 크기 및 작업의 다른 파인튜닝과 충돌을 피할 수 있습니다.

소스 디렉토리가 읽기 전용일 경우, 변환은 호출마다 생성되는 새로운 개인 임시 디렉토리로 대체되며, 로그 라인에는 사용된 경로가 표시됩니다. 이것도 실패할 경우에만 변환이 중단되며 경고가 표시됩니다.

## 기존 LibreYOLO 체크포인트

`libreyolo_version` 또는 `model_family`와 같은 LibreYOLO 전용 마커가 있는 파일은 일반 로드 경로에 속하며 다시 변환되지 않습니다. 스킵은 키셋이 변경되지 않은 패스스루 클레임에만 적용됩니다. 변환으로 키셋이 변경된 클레임은 외부 업스트림 레이아웃의 증거이며, 마커가 있는 파일에서도 허용됩니다.

`schema_version`는 의도적으로 마커로 처리되지 않는데, 다른 학습 도구와 내보내기 도구가 해당 일반 이름을 사용하기 때문이며, `names`, `nc`, `size`, `task` 또는 `imgsz`도 동일하게 처리되지 않는데, 상류 파인튜닝이 그것들을 포함할 수 있기 때문입니다. 따라서 단지 일반 `names` 키를 포함하는 외부 파인튜닝은 표시되지 않으며, 그 네이티브 키 기반 청구는 정상적으로 변환되고 텐서 헤드에서 클래스 수를 파생하며 잘못 로드되어 80 클래스가 되지 않습니다.

## 변환기가 읽는 메타데이터

클래스 이름은 최상위 `names` 키에서 가져오거나 `args` 또는 `hyper_parameters` 블록 안의 `class_names`에서 가져옵니다. 클래스 인덱스 대신 레이블을 키로 사용하는 이름 맵은 사용할 수 없으며, 생성된 기본값으로 대체됩니다. 탐지된 클래스 수보다 긴 이름 목록은 잘려서 사용됩니다. 범위를 벗어난 인덱스는 엄격한 유효성 검사기에서 실패하고 변환을 조용히 중단시키기 때문입니다.

상류 `args`는 일반 메타데이터로 전달되며, 문자열, 숫자, 불리언, 리스트 또는 딕셔너리가 아닌 값은 삭제되어 안전하지 않은 자료가 저장된 파일에 도달하지 않도록 합니다.

## RF-DETR COCO 정규화

상류 RF-DETR 체크포인트는 91 출력 분류 헤드를 제공하며, 이는 COCO의 90 클래스와 배경을 포함합니다. 자동 변환은 COCO RF-DETR을 COCO-80 규칙으로 정규화하며, 매핑은 후처리 단계에서 적용됩니다.

체크포인트는 정확히 80개의 이름을 포함하거나, 클래스 수를 80으로 선언하거나, `coco` 데이터셋 힌트를 가지고 있거나, 아예 클래스나 데이터셋 메타데이터가 없을 때 COCO로 취급됩니다. 마지막 경우가 중요합니다: 메타데이터가 없는 상위 상태 사전은 표준 COCO-사전학습 체크포인트이며, 배포되는 유일한 메타데이터 없는 91-출력 RF-DETR입니다.

진정한 커스텀 90-클래스 RF-DETR은 90개 클래스로 유지됩니다. 이름 목록, 명시적인 80이 아닌 클래스 수, 또는 COCO가 아닌 데이터셋 힌트로 식별되며, 따라서 메타데이터 없는 체크포인트 대체는 적용되지 않습니다. 데이터셋 힌트가 존재하는지 결정할 때 빈 자리 표시자는 무시됩니다.

## 제한

자동 변환은 공개된 상류 레이아웃을 인식합니다. 이는 아키텍처를 다시 작성하지 않으며, 포팅되지 않은 모델을 로드 가능하게 만들지도 않습니다. 어떤 패밀리도 파일을 주장하지 않을 때, 답변은 팩토리 인수가 아닌 변환 스크립트입니다: 저장소는 EoMT, PIDNet, EfficientDet을 포함하여 필요로 하는 패밀리들을 위해 `weights/convert_*.py`를 제공합니다.

변환은 또한 읽을 수 없는 메타데이터를 생성하지 않습니다. 크기, 작업 및 클래스 수는 텐서에서 가져오며; 이름은 파일에 존재하면 파일에서 가져오고, 존재하지 않으면 `class_i`로 생성됩니다.
